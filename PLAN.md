## Product decisions

- Use a three-step wizard:
  1. **Start here** — explain the workshop and five-person group context, make clear that roles are optional and groups may organise themselves as they wish, explain how to use GitHub Copilot, and introduce the “build small, then evolve” approach.
  2. **Choose an app** — propose a random idea by default, with shuffle, search, browse, and explicit selection; keep the starter prompt hidden until Step 3 so this remains a lightweight choice.
  3. **Make it yours** — show the starter prompt, the selected app’s ten second-act features, and the ten general Interesting prompts/ideas.
- Keep the wizard header visible at every step. It contains the NBB logo, the current step indicator, a Back control where applicable, and a persistent **Reset workshop** action.
- A page refresh must restore the current wizard step, selected idea, prompt deck positions, and any other UI state that matters. Reset is the explicit way to start over.
- The second-act and Interesting prompt areas should be content-first cards/sections, not a permanently sticky sidebar. They can use a responsive two-column layout on wide screens and a single column on small screens.
- “Show different second-act ideas” must work in-page: show a new, non-repeating batch/order from the selected idea’s ten stored features without reloading. Include a “See all 10” affordance so every feature remains directly copyable.
- “Try a different angle” must work in-page: rotate or shuffle the ten general prompts without reloading, with the currently featured prompt easy to copy and an option to view/copy all ten. Every angle prompt must assume the selected app has already been created and request an incremental modification; it must not repeat the starter prompt or ask Copilot to recreate the app from scratch.
- Preserve the original Confluence wording where it is useful, but normalize punctuation and remove the `01 - Foo` placeholder from the picker.
- Use `app-ideas.json` as the canonical data file. Do not maintain a second hand-edited copy inside TypeScript.

## Risks and mitigations

| Risk | Impact | Mitigation |
|---|---:|---|
| Generated JSON is malformed or drifts from the embedded data | High | Make JSON canonical, validate it at runtime and in CI, and remove the legacy embedded copy. |
| localStorage contains an incompatible prior state | Medium | Version the state schema, validate IDs, and safely reset invalid state. |
| Users mistake simulated apps/data for production or official information | Medium | Preserve the source constraints in the UI and in generated follow-up prompts. |
| GitHub Pages path differs by repository | Medium | Use `base: './'` and verify the built artifact from a Pages-like path. |
| Official logo or fonts cause cross-origin failures | Medium | Keep the logo local and keep the fonts embedded/local; no runtime NBB requests. |
| Ten-item decks become visually overwhelming | Medium | Show a compact batch with explicit “See all 10” and direct copy actions. |
| A reset accidentally destroys a group’s current work | Medium | Keep the action clearly labelled, visible in the header, and separate from the copy/build controls; the workshop state is disposable and can be recreated. |
| Browser clipboard permissions differ on Pages | Medium | Use the Clipboard API with a textarea fallback and clear manual-copy feedback. |
